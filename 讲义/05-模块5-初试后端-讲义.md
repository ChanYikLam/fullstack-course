模块 3-4 我们一直在写**前端**——用户能在浏览器里看到的东西。但那只是冰山一角：


## 第 1 节：什么是 API

**视频**: [B 站链接](https://www.bilibili.com/video/BV1cDT16HEkE) | **时长**: ~23 分钟

### 详细讲解

#### 1.1 API 不是神秘的东西

**API（Application Programming Interface）** 就是"程序对外提供能力的入口"。

举个例子：
- 你在餐厅点菜，菜单就是 API——你按菜单上的方式告诉服务员你要什么，后厨按菜单上的方式给你做出来
- 你在 ATM 机上取钱，ATM 的屏幕和按钮就是 API——你按照指示操作，ATM 给你吐钱

在编程世界里：
- ipify 的 API：你发个请求问"我的 IP 是多少？"，它回你一段 JSON `{"ip": "114.86.123.45"}`
- DeepSeek 的 API：你发一段对话历史过去，它回一段 AI 的回答

#### 1.2 RESTful API 的惯例

| HTTP 方法 | 操作 | 示例 |
|-----------|------|------|
| `GET` | 获取数据 | `GET /api/users` → 获取用户列表 |
| `POST` | 创建数据 | `POST /api/users` → 创建新用户 |
| `PUT` | 完整更新 | `PUT /api/users/1` → 完整替换用户 1 |
| `PATCH` | 部分更新 | `PATCH /api/users/1` → 修改用户 1 的某个字段 |
| `DELETE` | 删除数据 | `DELETE /api/users/1` → 删除用户 1 |

#### 1.3 JSON——API 的通用语言

```json
{
    "name": "张三",
    "age": 25,
    "skills": ["HTML", "CSS", "JavaScript"],
    "contact": {
        "email": "zhangsan@example.com",
        "phone": "13800138000"
    }
}
```

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式。它跟 JavaScript 的对象字面量很像，但几乎所有编程语言都能解析 JSON。

| 虚拟环境 | `venv`（`source .venv/bin/activate`） | `node_modules`（自动） |
| 安装命令 | `pip install xxx` | `npm install xxx` |
| 安装所有依赖 | `pip install -r requirements.txt` | `npm install` |

## 第 3 节：理解 HTTP，手搓一个 API（核心章节！）

**视频**: [B 站链接](https://www.bilibili.com/video/BV1jzKK6aExw) | **时长**: ~45 分钟

### 详细讲解

#### 3.1 HTTP 报文——前后端对话的全貌

一次 HTTP 通信就是**一去一回两段有格式的文本**：

```
╔══════════════════════════════════════════════════════════╗
║                      请求（去）                          ║
╠══════════════════════════════════════════════════════════╣
║ GET /api/profile HTTP/1.1          ← 请求行（方法+路径+版本）║
║ Host: localhost:8000               ← 请求头（附加信息）     ║
║ User-Agent: curl/8.7.1                                   ║
║ Accept: */*                                              ║
║                                    ← 空行（头和体的分界线） ║
║ （GET 请求通常没有请求体）                                  ║
╚══════════════════════════════════════════════════════════╝

╔══════════════════════════════════════════════════════════╗
║                      响应（回）                          ║
╠══════════════════════════════════════════════════════════╣
║ HTTP/1.1 200 OK                     ← 状态行（版本+状态码+说明）║
║ Content-Type: application/json      ← 响应头（内容的说明）  ║
║ Content-Length: 45                                       ║
║                                    ← 空行                ║
║ {"name": "张三", "age": 25}         ← 响应体（正文）       ║
╚══════════════════════════════════════════════════════════╝
```

#### 3.2 状态码速记

| 状态码 | 含义 | 什么时候见到 |
|--------|------|-------------|
| `200` | 成功 | 正常返回数据 |
| `201` | 创建成功 | POST 创建资源后 |
| `301` | 永久重定向 | 网址搬家了 |
| `400` | 请求有问题 | 参数不对、格式错误 |
| `401` | 未认证 | 没登录或 token 过期 |
| `403` | 禁止访问 | 你没权限 |
| `404` | 未找到 | URL 写错了或资源不存在 |
| `500` | 服务器内部错误 | 后端代码崩了 |

> **规律**：2xx 成功，3xx 重定向，4xx 你的问题，5xx 服务器的问题。

#### 3.3 手搓 API——逐行理解

下面是一段完整、可运行的 Python 代码。它做的事情就是"守在 8000 端口上，等待 HTTP 请求，按 HTTP 规范回话"。

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
import json

# ===== 要返回的数据 =====
profile = {
    "heroTitle": "关于我",
    "heroSubtitle": "项目，创意，灵感，心得，我的作品",
}

# ===== 请求处理器 =====
class Handler(BaseHTTPRequestHandler):
    
    def do_GET(self):
        """处理所有 GET 请求"""
        
        # 根据路径分发（这就是"路由"的原型！）
        if self.path == "/api/profile":
            # ─── 1. 状态行 ───
            self.send_response(200)
            # 缺少这一行 → 不是合法的 HTTP 响应 → 调用方报错
            
            # ─── 2. 响应头 ───
            self.send_header("Content-Type", "application/json")
            # 告诉调用方："我回的是 JSON 格式"
            # 如果写成 text/html，浏览器会当网页渲染
            self.send_header("Access-Control-Allow-Origin", "*")
            # 允许任何来源的前端页面调用（跨域）
            
            # ─── 3. 空行 ───
            self.end_headers()
            # 缺少这一行 → 调用方会把正文当成头来解析 → 全盘皆乱
            
            # ─── 4. 响应体 ───
            body = json.dumps(profile, ensure_ascii=False)
            # ensure_ascii=False → 中文原样输出，不转成 \uXXXX
            self.wfile.write(body.encode("utf-8"))
            # wfile = write file，往网络连接里写数据
            # encode → Python 字符串 → 网络传输的字节
            
        elif self.path == "/api/hello":
            self.send_response(200)
            self.send_header("Content-Type", "text/html; charset=utf-8")
            self.end_headers()
            self.wfile.write("<h1>你好，HTTP！</h1>".encode("utf-8"))
            
        else:
            # 没匹配到任何路径 → 404
            self.send_response(404)
            self.end_headers()
            # 注意：404 也要 end_headers()，这是硬要求

# ===== 启动服务器 =====
print("后端已启动：http://localhost:8000/api/profile")
print("按 Ctrl+C 停止")
HTTPServer(("", 8000), Handler).serve_forever()
# "" = 监听所有网络接口
# 8000 = 端口号
# serve_forever() = 一直运行，直到你按 Ctrl+C
```

#### 3.4 代码和 HTTP 规范的对应关系

| 代码行 | HTTP 规范里的角色 | 可不可以省略？ |
|--------|------------------|--------------|
| `self.send_response(200)` | 状态行 | **不可省略！** 删了就报错 |
| `self.send_header(...)` | 响应头 | 规范允许但实践必写 |
| `self.end_headers()` | 空行 | **不可省略！** 删了正文被当头解析 |
| `self.wfile.write(...)` | 响应体 | API 必须有，不然返回什么？ |
| `elif` / `else` | 路由分发 | 手写，代码里自己判断 |

### 实验：Content-Type 的威力

修改 `main.py` 中 `/api/hello` 的 `Content-Type`：

```python
# 实验 1：text/html → 浏览器当网页渲染
self.send_header("Content-Type", "text/html; charset=utf-8")
# 浏览器看到：一个大标题 <h1>你好，HTTP！</h1>

# 实验 2：改成 text/plain → 浏览器当纯文本显示
self.send_header("Content-Type", "text/plain; charset=utf-8")
# 浏览器看到：<h1>你好，HTTP！</h1> 原样输出
```

> **内容一个字没变，头一变，浏览器对内容的处理方式就变了。** 这就是响应头的威力。

## 第 4 节：FastAPI 入门

**视频**: [B 站链接](https://www.bilibili.com/video/BV1LW3K63ExS) | **时长**: ~36 分钟

### 详细讲解

#### 4.1 手搓版 vs FastAPI 版

**手搓版（约 25 行，只管了一个 GET 接口）**：
```python
class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/api/profile":
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.end_headers()
            body = json.dumps(profile, ensure_ascii=False)
            self.wfile.write(body.encode("utf-8"))
        else:
            self.send_response(404)
            self.end_headers()
```

**FastAPI 版（5 行，功能完全一样）**：
```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/api/profile")
def get_profile():
    return {"heroTitle": "关于我", "heroSubtitle": "..."}
```

框架帮我们做了：路由分发、状态行、响应头、空行、JSON 序列化、编码。

#### 4.2 FastAPI 帮你做的事一览

| HTTP 规范要求 | 手搓版（你要写） | FastAPI 版（框架替你写） |
|--------------|----------------|------------------------|
| 路由判断 | `if self.path == "..."` | `@app.get("/...")` |
| 状态行 | `self.send_response(200)` | 自动 |
| Content-Type | `self.send_header("Content-Type", ...)` | 自动 |
| CORS 头 | `self.send_header("Access-Control-Allow-Origin", ...)` | 加中间件 |
| 空行 | `self.end_headers()` | 自动 |
| JSON 序列化 | `json.dumps(data)` | 自动 |
| 编码 | `.encode("utf-8")` | 自动 |
| 写响应体 | `self.wfile.write(...)` | 自动 |

#### 4.3 FastAPI 核心概念

| 概念 | 说明 | 示例 |
|------|------|------|
| `FastAPI()` | 创建应用实例 | `app = FastAPI()` |
| 路由装饰器 | 声明哪个函数处理哪个路径的哪种方法 | `@app.get("/users")` |
| 路径参数 | URL 中的动态部分 | `@app.get("/users/{user_id}")` |
| 查询参数 | URL `?` 后面的参数 | `@app.get("/search?q=xxx")` |
| 请求体 | POST/PUT 提交的 JSON 数据 | 用 Pydantic 模型定义 |
| `uvicorn` | 把 FastAPI 应用跑起来的服务器 | `uvicorn main:app --reload` |
| `/docs` | 自动生成的交互式 API 文档 | 访问 `http://localhost:8000/docs` |

**fastapi_main.py**：
```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
from typing import Optional

# ===== 创建应用 =====
app = FastAPI(
    title="我的第一个 FastAPI 应用",
    description="从手搓到框架的完整历程",
    version="1.0.0"
)

# ===== 允许跨域（让前端能调用） =====
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)

# ===== 数据 =====
profile = {
    "heroTitle": "关于我",
    "heroSubtitle": "项目，创意，灵感，心得，我的作品",
}

# ===== GET 接口 =====

@app.get("/api/profile")
def get_profile():
    """获取个人信息"""
    return profile

@app.get("/api/hello")
def hello():
    """返回一个简单的问候"""
    return {"message": "你好，来自 FastAPI！"}

# 路径参数示例
@app.get("/api/users/{user_id}")
def get_user(user_id: int):
    """根据 ID 获取用户信息"""
    return {"user_id": user_id, "name": f"用户{user_id}"}

# 查询参数示例
@app.get("/api/search")
def search(q: str = "", page: int = 1):
    """搜索接口 ?q=关键词&page=1"""
    return {
        "query": q,
        "page": page,
        "results": [f"{q}相关结果1", f"{q}相关结果2"]
    }

# ===== POST 接口 =====

# Pydantic 模型——定义请求体的数据结构
class CreateItem(BaseModel):
    name: str
    price: float
    description: Optional[str] = None

@app.post("/api/items")
def create_item(item: CreateItem):
    """创建一个新项目"""
    # FastAPI 自动校验：name 必须是字符串，price 必须是数字
    # 如果不符合，自动返回 422 错误
    return {
        "message": f"创建成功：{item.name}",
        "item": item.model_dump()
    }

# ===== 启动 =====
# 运行命令：uvicorn fastapi_main:app --reload
# fastapi_main = 文件名（不含 .py）
# app = FastAPI() 实例的变量名
# --reload = 代码修改后自动重启（开发模式）
```

```bash
# 启动 FastAPI 应用
uvicorn fastapi_main:app --reload

# 终端输出：
# INFO:     Uvicorn running on http://127.0.0.1:8000
# INFO:     Application startup complete.

# ===== 测试各个接口 =====

# 在新终端中：

# GET 请求
curl http://localhost:8000/api/profile
curl http://localhost:8000/api/hello
curl http://localhost:8000/api/users/42
curl 'http://localhost:8000/api/search?q=React&page=2'

# POST 请求
curl -X POST http://localhost:8000/api/items \
  -H "Content-Type: application/json" \
  -d '{"name": "笔记本电脑", "price": 5999}'

# POST 请求（故意写错——price 是字符串，FastAPI 会拒绝）
curl -X POST http://localhost:8000/api/items \
  -H "Content-Type: application/json" \
  -d '{"name": "笔记本电脑", "price": "五九九九"}'
# 返回 422 Unprocessable Entity——自动校验！

# ===== 访问自动文档 =====
# 浏览器打开：http://localhost:8000/docs
# 你会看到一个交互式的 API 文档页面（Swagger UI）
# 可以直接在这里测试接口！
```

## 课后作业

### 基础题（必做）

1. **API 概念**：
   - 用自己的话解释什么 API，举一个生活中的例子
   - 写出 RESTful API 的五种 HTTP 方法及其含义

2. **Python 环境**：
   - 创建虚拟环境并激活
   - 安装 `requests` 和 `fastapi` + `uvicorn`
   - 生成 `requirements.txt`

3. **手搓 API**：
   - 用 `http.server` 手写一个 API 服务器，包含：
     - `GET /api/status` → 返回 `{"status": "ok", "time": "当前时间"}`
     - `GET /api/echo?message=xxx` → 返回 `{"echo": "xxx"}`
   - 用 `curl -v` 查看完整报文

4. **FastAPI 迁移**：
   - 用 FastAPI 重写上面两个接口
   - 添加一个 POST 接口：
     - `POST /api/messages` → 接收 `{"name": "...", "content": "..."}`，返回 `{"id": 1, ...}`
   - 访问 `/docs` 文档页面验证

### 进阶题（选做）

5. **HTTP 实验**：
   - 手搓版中，故意删掉 `self.end_headers()`，用 `curl -v` 观察发生了什么
   - 修改 `Content-Type` 为 `text/plain`，用浏览器访问，观察效果

6. **Pydantic 模型**：
   - 给 POST 接口的请求体添加更多字段验证（长度限制、范围限制、正则匹配等）

### 挑战题

7. **MVC 结构**：
   - 将 FastAPI 项目拆分成多文件结构：
     ```
     backend/
     ├── main.py          (FastAPI 入口)
     ├── routers/         (路由)
     │   ├── users.py
     │   └── items.py
     ├── models/          (Pydantic 模型)
     │   └── schemas.py
     └── services/        (业务逻辑)
         └── user_service.py
     ```

8. **前后端联通**：
   - 用模块 4 学的 React/Next.js 创建一个简单的前端页面
   - 前端调用你写的 FastAPI 接口
   - 把后端数据展示在页面上
