### 从"手工时代"到"工业化时代"

模块 3 我们手写 HTML、CSS、JS，这就像用手工工具盖一间小木屋——完全可以，而且能很好地理解每个部件。

但当房子要盖 20 层时，你不能继续用锤子和手锯。你需要塔吊、预制板、标准件——这就是现代前端工具要做的事。

```
手工时代（模块 3）                工业化时代（模块 4）
┌──────────────┐              ┌──────────────┐
│ HTML         │              │ React 组件    │
│ + CSS        │  ── Vite ──→ │ + CSS Module  │
│ + JS         │  (翻译官)    │ + JSX         │
│              │              │               │
│ 手动引入      │              │ 自动打包       │
│ 手动刷新      │              │ 热更新         │
│ 全局变量      │              │ 模块作用域     │
└──────────────┘              └──────────────┘
```

### 核心概念一句话总结

- **模块化**：把一个大文件拆成小文件，各管各的
- **npm**：下载别人写好的代码包（不用自己从零造轮子）
- **Vite**：把你写的"高级代码"翻译成浏览器认识的"基础代码"
- **React**：用"组件"的方式搭界面，数据变了界面自动变
- **Next.js**：在 React 基础上，把路由、SEO、优化全帮你搞定

## 第 1 节：现代前端基础——模块化

**视频**: [B 站链接](https://www.bilibili.com/video/BV1fmEi6DE9b) | **时长**: ~37 分钟

### 详细讲解

#### 1.1 模块化解决的问题

没有模块化时，所有的 JavaScript 都写在一个文件里。500 行的代码还能忍，5000 行呢？

```js
// 一个 5000 行的 main.js——你的噩梦：
// ... 第 1-300 行：导航栏逻辑
// ... 第 301-800 行：表单验证
// ... 第 801-1200 行：轮播图
// ... 第 1201-2000 行：数据请求
// ...（已经不知道哪个函数在做什么了）

// 变量的名字也会打架：
var name = "张三";    // 第 50 行
var name = "李四";    // 第 2000 行——完蛋，覆盖了！
```

模块化之后：
```js
// nav.js —— 只管导航
export function initNav() { ... }

// form.js —— 只管表单
export function initForm() { ... }

// main.js —— 总入口
import { initNav } from "./nav.js";
import { initForm } from "./form.js";

initNav();
initForm();
```

> **每个模块有自己的作用域**——nav.js 里面定义的变量，form.js 是看不见的。再也不怕变量名字打架了。

#### 1.2 两种导出方式

```js
// ===== 命名导出 =====
// utils.js
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }
export const PI = 3.14159;

// 使用时需要精确的名字：
import { add, PI } from "./utils.js";

// ===== 默认导出 =====
// calculator.js
export default function calculate(expression) {
    // ... 复杂的计算逻辑
}

// 使用时可以随意命名：
import calc from "./calculator.js";
calc("1 + 2");

// ===== 混合使用 =====
import calc, { add, PI } from "./math.js";
```

### 详细讲解

#### 2.1 三个新角色登场

| 工具 | 是什么 | 你什么时候需要它 | 类比 |
|------|------|----------------|------|
| **Node.js** | 让 JS 能在电脑本地运行（不局限于浏览器） | Vite 需要它、npm 需要它 | Java 的 JVM |
| **npm** | 包管理器——下载别人写好的代码 | 安装 React、Vite 等工具时 | 手机的应用商店 |

#### 2.2 npm 核心概念

```bash
npm init -y          # 初始化项目，创建 package.json
npm install xxx      # 安装包，写入 dependencies
npm install -D xxx   # 安装开发依赖（只在开发时用）
npm install          # 根据 package.json 安装所有依赖
npm run dev          # 运行 package.json 中 scripts 定义的命令
```

#### 2.3 `package.json` 详解

```json
{
    "name": "my-project",           // 项目名
    "version": "1.0.0",             // 版本号
    "scripts": {                    // 可执行的命令
        "dev": "vite",              // npm run dev → 启动开发服务器
        "build": "vite build",      // npm run build → 构建生产版本
        "preview": "vite preview"   // npm run preview → 预览构建结果
    },
    "dependencies": {               // 运行时需要的依赖（用户也要用）
        "react": "^18.2.0",
        "react-dom": "^18.2.0"
    },
    "devDependencies": {            // 开发时需要的依赖（只开发时用）
        "vite": "^5.0.0",
        "@vitejs/plugin-react": "^4.0.0"
    }
}
```

#### 2.4 `node_modules` 和 `.gitignore`

`node_modules` 是 npm 下载的所有包存放的地方。这个文件夹可能非常大（几百 MB），**千万不要提交到 Git**。

```gitignore
node_modules/
dist/
.env
.DS_Store
```

别人拿到你的项目后，只需要 `npm install`，npm 会根据 `package.json` 自动下载所有依赖。

## 第 3 节：React——前端开发新规则

**视频**: [B 站链接](https://www.bilibili.com/video/BV1FX7F6UEWq) | **时长**: ~56 分钟  
**配套代码**: `cd zero-to-tech-demos/zero-to-tech-4-3`

### 详细讲解

#### 3.1 什么是组件？

```
传统方式（按文件类型分）：        React 方式（按界面单元分）：
┌──────────┐                  ┌──────────────┐
│ HTML 文件 │ ← 所有结构       │ 导航栏组件     │ ← 结构+样式+逻辑
├──────────┤                  │  ┌──────────┐ │
│ CSS 文件  │ ← 所有样式       │  │ HTML结构  │ │
├──────────┤                  │  │ CSS样式   │ │
│ JS 文件   │ ← 所有逻辑       │  │ JS交互    │ │
└──────────┘                  │  └──────────┘ │
                              ├──────────────┤
                              │ 卡片组件       │
                              │  ┌──────────┐ │
                              │  │ HTML结构  │ │
                              │  │ CSS样式   │ │
                              │  │ JS交互    │ │
                              │  └──────────┘ │
                              └──────────────┘
```

> **一个组件 = 数据 + 结构 + 样式 + 行为，封装成一个能独立拎走的 UI 单元。**

#### 3.2 浏览器不认识 React

```
你写的是：                    浏览器认识的是：
┌─────────────────┐         ┌─────────────────┐
│ function Card() {│         │ <div class="card">│
│   return (       │  Vite   │   <h3>标题</h3>  │
│     <div className│ ─────→ │   <p>内容</p>    │
│       <h3>标题   │ 翻译    │ </div>           │
│       <p>内容    │         │                 │
│     </div>       │         │ <style>         │
│   );             │         │   .card { ... } │
│ }                │         │ </style>        │
└─────────────────┘         └─────────────────┘
```

这就是为什么 React 项目需要 Vite（加 `@vitejs/plugin-react` 插件）——Vite 需要这个插件才知道怎么"翻译"React 代码。

#### 3.5 JSX 关键规则

```jsx
function DemoComponent() {
    const title = "演示组件";
    const items = ["苹果", "香蕉", "橘子"];
    const isActive = true;
    
    return (
        <div>
            {/* 1. 大括号里写 JavaScript 表达式 */}
            <h1>{title}</h1>
            <p>现在时间是：{new Date().toLocaleTimeString()}</p>
            
            {/* 2. 用 map 渲染列表——React 里非常常见 */}
            <ul>
                {items.map((item, index) => (
                    <li key={index}>{item}</li>
                    // 注意 key prop！React 用它来追踪每个列表项
                ))}
            </ul>
            
            {/* 3. class 写作 className */}
            <div className={isActive ? "active" : "inactive"}>
                {/* 4. 条件渲染 */}
                {isActive && <span>激活状态</span>}
                {isActive ? <span>是</span> : <span>否</span>}
            </div>
        </div>
    );
}
```

## 第 4 节：数据驱动界面

**视频**: [B 站链接](https://www.bilibili.com/video/BV1Dg7H6oEHQ) | **时长**: ~42 分钟  
**配套代码**: `cd zero-to-tech-demos/zero-to-tech-4-4`

### 详细讲解

#### 4.1 两种思路对比

**传统思路（直接操作 DOM）**：
```js
// 你需要手动找到元素、修改内容、管理状态
let count = 0;

document.getElementById("btn").addEventListener("click", () => {
    count++;
    document.getElementById("display").textContent = count;
    // 如果页面上有三个地方要显示 count——你得手动更新三次！
});
```

**React 思路（数据驱动界面）**：
```jsx
// 你只需要改数据——React 自动更新所有用到这个数据的地方
function Counter() {
    const [count, setCount] = useState(0);
    
    return (
        <div>
            <span>{count}</span>         {/* 自动更新 */}
            <span>双倍: {count * 2}</span> {/* 自动更新 */}
            <button onClick={() => setCount(count + 1)}>+1</button>
        </div>
    );
}
```

> **React 的最大变化：把"操作页面"变成了"改变数据"。** 数据变了，页面自动变得更新的样子。你不需要手动去更新任何一个 DOM 元素。

#### 4.2 `useState` 详解

```jsx
import { useState } from "react";

function TodoList() {
    // useState 返回 [当前值, 修改函数]
    const [todos, setTodos] = useState(["学习 React", "写代码"]);
    const [input, setInput] = useState("");
    
    function addTodo() {
        // 不要这样写：todos.push(input)
        // React 不知道数组被改了，不会重新渲染！
        
        // 正确方式：用 setTodos 传入新数组
        setTodos([...todos, input]);
        // ...todos 展开旧数组 + 新项目 = 新数组
        setInput("");  // 清空输入框
    }
    
    return (
        <div>
            <input 
                value={input} 
                onChange={(e) => setInput(e.target.value)}
                placeholder="输入待办事项"
            />
            <button onClick={addTodo}>添加</button>
            <ul>
                {todos.map((todo, i) => (
                    <li key={i}>{todo}</li>
                ))}
            </ul>
        </div>
    );
}
```

#### 4.3 `useEffect` 详解

```jsx
import { useState, useEffect } from "react";

function Clock() {
    const [time, setTime] = useState(new Date());
    
    useEffect(() => {
        // 组件"出现"在页面上之后执行
        console.log("时钟启动");
        
        const timer = setInterval(() => {
            setTime(new Date());
        }, 1000);
        
        // 返回的函数在组件"消失"时执行
        return () => {
            console.log("时钟停止");
            clearInterval(timer);
        };
    }, []);  // 空数组 = 只在挂载/卸载时执行一次
    
    return <h1>{time.toLocaleTimeString()}</h1>;
}
```

#### 4.4 核心原则

```
数据（State）  ──── 驱动 ────→  界面（JSX）
     │                              │
     │                              │
     └─── 用户交互 ──── 改变 ───────┘
         （setState）
```

这个单向循环就是 React 的核心工作方式。

## 第 5 节：看懂 Next.js

**视频**: [B 站链接](https://www.bilibili.com/video/BV1NxK962E2t) | **时长**: ~35 分钟  
**配套代码**: `cd zero-to-tech-demos/zero-to-tech-4-5`

### 详细讲解

#### 5.1 React 没做的事，Next.js 来补

| 问题 | React 本身 | Next.js 方案 |
|------|-----------|-------------|
| 不同 URL 显示不同页面（路由） | 需要额外库（react-router） | 文件即路由：`app/about/page.jsx` → `/about` |
| SEO（搜索引擎看不懂 JS 渲染的页面） | 搜索引擎可能只看到空壳 | 服务端渲染（SSR）：搜索引擎拿到完整 HTML |
| 首屏加载慢（JS 太大） | 用户要等 JS 下载完才能看到页面 | 静态生成（SSG）：构建时就生成好 HTML |
| 数据获取 | 只能在前端 fetch | 可以在服务端直接查数据库 |

#### 5.2 三种渲染方式

```
CSR (Client-Side Rendering)    SSR (Server-Side Rendering)    SSG (Static Site Generation)
┌────────┐                      ┌────────┐                    ┌────────┐
│ 浏览器  │                      │ 服务器  │                    │ 构建时  │
│ 下载JS  │                      │ 渲染页面 │                    │ 生成页面 │
│ 执行JS  │                      │ 返回HTML │                    │ 保存HTML │
│ 渲染页面 │                      │ 浏览器  │                    │ 浏览器  │
└────────┘                      │ 直接显示 │                    │ 直接显示 │
  慢                            └────────┘                    └────────┘
                                 快                            最快
```

}

## 第 6 节：Next.js 项目的两种部署方式

**视频**: [B 站链接](https://www.bilibili.com/video/BV1FiTq6fE8N) | **时长**: ~28 分钟

### 详细讲解

#### 6.1 方式一：Node 服务部署

```bash
npm run build      # 构建
npm run start      # 启动 Node.js 服务（默认端口 3000）
```

**优点**：支持所有 Next.js 功能（SSR、API Routes、中间件等）  
**缺点**：需要服务器持续运行 Node.js 进程（用 pm2 守护进程管理）

```bash
# 在服务器上
npm install -g pm2
pm2 start npm --name "my-app" -- start
pm2 save
pm2 startup  # 设置开机自启
```

#### 6.2 方式二：静态导出 + Nginx

修改 `next.config.js`：
```js
const nextConfig = {
    output: "export",  // 启用静态导出
};
```

```bash
npm run build
# 生成 out/ 文件夹（纯静态 HTML/CSS/JS）
```

把 `out/` 文件夹的内容放到 Nginx 的 `root` 目录下即可。

**优点**：部署简单，不需要 Node.js 运行时  
**缺点**：不能用服务端功能（SSR、API Routes、动态路由等）
