## 第 1 节：什么是 API

**视频**: [5.1](https://www.bilibili.com/video/BV1cDT16HEkE) | **时长**: ~23 分钟  
**配套课件**: https://xn--ygr25xpohxwz.com/zero-to-fullstack/lessons/module-5-1/

### 知识点

| 知识点 | 说明 |
|--------|------|
| API 是什么 | Application Programming Interface——程序对外提供能力的入口 |
| API 不神秘 | 它就是你"叫别人帮忙做一件事"的约定方式 |
| 后端是什么 | 一个一直运行、守着等请求、收到请求后处理并返回结果的程序 |
| RESTful API | 用 HTTP 方法（GET/POST/PUT/DELETE）描述操作意图 |
| JSON | JavaScript Object Notation——API 通信中最常用的数据格式 |
| curl | 命令行 HTTP 客户端——在终端里发 HTTP 请求 |
| 真实 API 体验 | 调用 ipify（查公网 IP）和 DeepSeek（AI 对话）两个真实 API |

### 实操练习

```bash
# 1. 调用 ipify——查询你的公网 IP
curl 'https://api.ipify.org?format=json'
# 返回: {"ip":"114.86.123.45"}

# 2. 调用 DeepSeek API（需要 API Key）
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer 你的API_KEY" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "你好，用一句话介绍你自己"}]
  }'
```

### curl 参数速记

| 参数 | 含义 |
|------|------|
| `-H "Key: Value"` | 添加一个请求头 |
| `-d '...'` | 添加请求体（POST 数据） |
| `-v` | verbose——显示完整的请求和响应报文 |
| `-X POST` | 指定 HTTP 方法（默认 GET，有 `-d` 时自动 POST） |

### 核心理解

> API 没有另起炉灶——它直接用了浏览器上网用的那套 HTTP 规矩。所谓"调用 API"，本质上就是一次 HTTP 请求，只不过返回的是 JSON 数据而不是网页。

## 第 3 节：理解 HTTP，手搓一个 API

**视频**: [5.3](https://www.bilibili.com/video/BV1jzKK6aExw) | **时长**: ~45 分钟  
**配套课件**: https://xn--ygr25xpohxwz.com/zero-to-fullstack/lessons/module-5-3/

### 知识点（重点模块！）

| 知识点 | 说明 |
|--------|------|
| HTTP 报文格式 | 请求 = 请求行 + 头 + 空行 + 体；响应 = 状态行 + 头 + 空行 + 体 |
| 请求行 | `方法 路径 协议版本`——如 `GET /api/profile HTTP/1.1` |
| 状态行 | `协议版本 状态码 简短说明`——如 `HTTP/2 200 OK` |
| HTTP 方法 | GET（取数据）、POST（提交数据）、PUT、PATCH、DELETE |
| 状态码家族 | 2xx 成功、4xx 请求方问题、5xx 服务方问题 |
| 请求头 | `Host`、`User-Agent`、`Content-Type`、`Authorization` 等 |
| 响应头 | `Content-Type`（指定返回格式）、`Content-Length`、`Server`、`Date` |
| `curl -v` | 显示一次请求的完整报文（`>` 请求原文、`<` 响应原文、`*` 旁白） |
| F12 Network | 浏览器开发者工具中查看每次 HTTP 请求的完整细节 |
| HTTP/1.1 vs HTTP/2 | 协议版本——语义相同（方法、状态码、头不变），传输方式不同 |

### HTTP 报文结构

```
请求                          响应
├─ 请求行（方法+路径+版本）    ├─ 状态行（版本+状态码+说明）
├─ 请求头（若干行 key:value）  ├─ 响应头（若干行 key:value）
├─ 空行                        ├─ 空行
└─ 请求体                      └─ 响应体
```

### 用 curl -v 验证

```bash
curl -v 'https://api.ipify.org?format=json'
```

逐行指认：`>` 开头的是发出去的请求，`<` 开头的是收到的响应。请求行、头、空行、体——每个部件都能找到。

### 手搓 API（用 Python 标准库）

创建一个零依赖的 API 服务器：

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
import json

profile = {
    "heroTitle": "关于我",
    "heroSubtitle": "项目，创意，灵感，心得，我的作品",
}

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/api/profile":
            # 状态行
            self.send_response(200)
            # 响应头
            self.send_header("Content-Type", "application/json")
            # 空行（头与体的分界线）
            self.end_headers()
            # 响应体
            body = json.dumps(profile, ensure_ascii=False)
            self.wfile.write(body.encode("utf-8"))
        else:
            self.send_response(404)
            self.end_headers()

print("后端已启动：http://localhost:8000/api/profile")
HTTPServer(("", 8000), Handler).serve_forever()
```

### 代码 vs 规范对照

| 代码 | 对应 HTTP 规范里的 |
|------|-------------------|
| `do_GET(self)` | 请求行里的**方法**——GET 请求的处理入口 |
| `self.path` | 请求行里的**路径**——对方要访问哪个资源 |
| `self.send_response(200)` | 响应的**状态行**——必写，不写就会报错 |
| `self.send_header(...)` | **响应头**——这里是 `Content-Type` |
| `self.end_headers()` | **空行**——头写完了，下面开始是体（必写！） |
| `self.wfile.write(...)` | **响应体**——真正给对方的 JSON 数据 |

### 核心心法

> **这三行不是样板代码：** `send_response`（状态行）+ `end_headers`（空行）+ `send_header("Content-Type")`（响应头）——删掉任何一样，要么直接报错，要么调用方没法正确解析。

## 第 4 节：FastAPI 入门

**视频**: [5.4](https://www.bilibili.com/video/BV1LW3K63ExS) | **时长**: ~36 分钟  
**配套课件**: https://xn--ygr25xpohxwz.com/zero-to-fullstack/lessons/module-5-4/

### 知识点

| 知识点 | 说明 |
|--------|------|
| FastAPI 是什么 | 现代 Python Web 框架——帮我们干完所有 HTTP 杂活 |
| uvicorn | ASGI 服务器——把 FastAPI 应用跑起来的"引擎" |
| 为什么需要框架 | 手搓 API 时我们干了太多杂活：路由、状态行、响应头、请求体解析、JSON 序列化…… |
| 框架替我们做了什么 | 路由自动分发、状态码自动设置、响应头自动添加、请求体自动解析 |
| 路由装饰器 | `@app.get("/api/profile")`——声明这个函数处理什么路径的什么方法 |
| POST 方法 | `@app.post("/api/submit")`——接收并处理客户端提交的数据 |
| Pydantic 模型 | 定义请求体和响应体的数据结构，自动校验 |
| 自动文档 | FastAPI 自带 Swagger UI——`/docs` 路径自动生成交互式 API 文档 |

### 从手搓到框架的对比

**手搓版（约 20 行，只管了一个 GET 接口）**:
```python
class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/api/profile":
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.end_headers()
            body = json.dumps(profile, ensure_ascii=False)
            self.wfile.write(body.encode("utf-8"))
        else:
            self.send_response(404)
            self.end_headers()
```

**FastAPI 版（同样功能，只需要 5 行）**:
```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/api/profile")
def get_profile():
    return {"heroTitle": "关于我", "heroSubtitle": "项目，创意，灵感，心得，我的作品"}
```

### FastAPI POST 示例

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float

@app.post("/api/items")
def create_item(item: Item):
    return {"message": f"收到了 {item.name}，价格 {item.price}"}
```

### 启动

```bash
pip install fastapi uvicorn
uvicorn main:app --reload
# 访问 http://localhost:8000/docs → 自动生成的交互式文档
```

### 核心心法

> 框架不是魔法——它只是替我们干了那些"每个项目都要做、但和业务逻辑无关"的 HTTP 杂活。正因为我们手搓过一遍，所以能确切知道 FastAPI 替我们干了什么。
