## 第 1 节：域名注册与 DNS 配置

### 详细讲解

#### 1.1 域名的结构

```
https://www.example.com/posts/hello-world
  │      │      │       │       │
  协议   子域名  根域名   顶级域   路径
```

- **顶级域（TLD）**：`.com`、`.cn`、`.org`、`.xyz` 等
- **根域名**：`example`——你注册的名字
- **子域名**：`www`、`api`、`blog` 等——一个域名可以有多个子域名

#### 1.2 DNS 解析记录

当你买了域名，你需要告诉 DNS"这个域名指向哪个 IP"：

| 记录类型 | 作用 | 示例 |
|----------|------|------|
| A 记录 | 域名 → IPv4 地址 | `example.com` → `123.45.67.89` |
| AAAA 记录 | 域名 → IPv6 地址 | `example.com` → `2001:db8::1` |
| CNAME 记录 | 域名 → 另一个域名 | `www.example.com` → `example.com` |
| MX 记录 | 邮件服务器 | 收邮件用的 |

#### 1.3 常见设置

```
主机记录    记录类型    记录值
@          A          123.45.67.89    ← 根域名
www        CNAME      example.com    ← www 跳转到根域名
api        A          123.45.67.89    ← API 子域名（可选）
```

**注意**：DNS 修改后需要一定时间生效（TTL，Time To Live）。通常几分钟到几小时不等。如果设置了但访问不到，先等一等。

#### 1.4 Nginx 多站点配置

如果你一台服务器上有多个网站，Nginx 通过 `server_name` 区分：

```nginx
# 博客
server {
    listen 80;
    server_name blog.example.com;
    root /var/www/blog;
}

# API 服务（反向代理到 FastAPI）
server {
    listen 80;
    server_name api.example.com;
    location / {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> **反向代理**的意思是：Nginx 接收外部请求，转发给内部的 FastAPI（端口 8000），拿到响应后再返回给用户。用户不知道背后有 FastAPI——他们只跟 Nginx 打交道。

## 第 2 节：HTTPS——Let's Encrypt 免费证书

### 详细讲解

#### 2.1 HTTP 的不安全之处

HTTP 数据在网络上是**明文传输**的。任何能在中间截获数据包的人（公共 WiFi、路由器管理员、运营商）都能看到你发了什么、收到了什么。

```
HTTP：
客户端 ── 明文 "password=123456" ──→ 服务器
         ↑ 任何中间人都能看到！

HTTPS：
客户端 ── 加密 "A7x$k2..." ──→ 服务器
         ↑ 只有服务器能解密
```

#### 2.2 SSL/TLS 证书的工作原理

1. 服务器生成一对密钥：公钥和私钥
2. 你去证书颁发机构（CA）申请证书——CA 验证"你真的拥有这个域名"
3. CA 给你签发一个证书（包含你的公钥 + CA 的数字签名）
4. 浏览器访问时，服务器出示证书
5. 浏览器验证证书签名（信任链：Let's Encrypt → 你）
6. 验证通过 → 建立加密连接

**Let's Encrypt** 是目前最广泛使用的免费 CA，由非营利组织运营。

#### 2.3 Certbot 自动化

```bash
# 一条命令搞定
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
```

Certbot 做的事情：
1. 验证你确实拥有 `yourdomain.com`（在你的服务器上放一个验证文件）
2. 向 Let's Encrypt 申请证书
3. 下载证书到你服务器
4. 自动修改 Nginx 配置（添加 443 端口、指向证书文件）
5. 设置定时任务自动续期（`certbot renew`）

### 课堂演示代码

```bash
# 应该看到锁图标 + "连接是安全的"
```

## 第 3 节：进程守护

### 详细讲解

#### 3.1 为什么 `python3 main.py` 不够？

当你 SSH 登录服务器，输入 `python3 main.py`：
- 程序在前台运行
- 你关了终端 → 程序也停了
- 服务器重启 → 程序不会自动启动
- 程序崩溃 → 没人帮你重启

**进程管理器**解决了所有这些问题。

#### 3.2 进程管理器对比

| | systemd | pm2 | Supervisor |
|------|---------|-----|-----------|
| 适用 | Linux 系统服务 | Node.js 项目 | Python 传统方案 |
| 安装 | 系统自带 | `npm install -g pm2` | `apt install supervisor` |
| 配置 | `.service` 文件 | `pm2 start` 命令 | `.conf` 文件 |
| 开机自启 | `systemctl enable` | `pm2 startup` | 自动（安装为系统服务） |
| 日志 | `journalctl` | `pm2 logs` | 配置文件中指定 |

### 课堂演示代码

#### systemd 配置 FastAPI

```bash
# 1. 创建 systemd 服务文件
sudo vim /etc/systemd/system/blog-api.service
```

```ini
[Unit]
Description=Blog API (FastAPI)
# 描述——systemctl status 时显示
After=network.target
# 在网络启动之后再启动这个服务

[Service]
Type=simple
User=ubuntu
# 以 ubuntu 用户身份运行（不要用 root）

WorkingDirectory=/home/ubuntu/blog/backend
# 工作目录——Python 的 os.getcwd() 会返回这里

Environment="PATH=/home/ubuntu/blog/backend/.venv/bin:/usr/bin"
# 指定 Python 虚拟环境的路径

EnvironmentFile=/home/ubuntu/blog/backend/.env
# 从 .env 文件加载环境变量

ExecStart=/home/ubuntu/blog/backend/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
# 启动命令——必须用虚拟环境里的 uvicorn 的完整路径！
# --host 0.0.0.0 允许外部访问（否则只有本机能访问）
# --port 8000 监听端口

Restart=always
# 程序崩溃 → 自动重启

RestartSec=3
# 崩溃后等 3 秒再重启（防止疯狂重启）

[Install]
WantedBy=multi-user.target
# 在系统进入多用户模式时启动（即开机自启）
```

```bash
# 2. 重新加载 systemd 配置
sudo systemctl daemon-reload

# 3. 启动服务
sudo systemctl start blog-api

# 4. 设置开机自启
sudo systemctl enable blog-api

# 5. 检查状态
sudo systemctl status blog-api
# 应该看到 Active: active (running)

# 6. 查看日志
sudo journalctl -u blog-api -f
# -u blog-api: 只看这个服务的日志
# -f: 实时追踪（follow），类似 tail -f
# 按 Ctrl+C 退出

# 7. 日常管理命令
sudo systemctl status blog-api    # 状态
sudo systemctl restart blog-api   # 重启
sudo systemctl stop blog-api      # 停止
sudo systemctl start blog-api     # 启动
sudo systemctl disable blog-api   # 取消开机自启
```

```bash
# 1. 安装 pm2（全局安装）
```

#### Nginx 反向代理到 Next.js

```nginx
server {
    listen 443 ssl;
    server_name yourdomain.com www.yourdomain.com;

    # SSL 证书（Certbot 自动配置的）
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://localhost:3000;  # Next.js 运行在 3000
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 第 4 节：日志与监控

### 详细讲解

#### 4.1 日志的核心原则

1. **日志要输出到文件，不只终端**
2. **日志要分级别**——DEBUG 看细节，ERROR 看问题
3. **日志要有时间戳**——知道"什么时候发生了什么"
4. **日志不要存敏感信息**——密码、token、身份证号等脱敏或不上日志
5. **日志要轮转**——否则一个文件无限增长，迟早撑爆磁盘

#### 4.2 Python logging 实战

```python
# logger.py —— 统一日志配置
import logging
import sys
from logging.handlers import RotatingFileHandler
import os

def setup_logger(name: str = "app") -> logging.Logger:
    logger = logging.getLogger(name)
    logger.setLevel(logging.INFO)

    # 格式
    fmt = logging.Formatter(
        "%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S"
    )

    # 输出到文件（带轮转）
    os.makedirs("logs", exist_ok=True)
    file_handler = RotatingFileHandler(
        "logs/app.log",
        maxBytes=10 * 1024 * 1024,  # 10MB 一个文件
        backupCount=5,                # 保留 5 个旧文件
        encoding="utf-8"
    )
    file_handler.setLevel(logging.INFO)
    file_handler.setFormatter(fmt)
    logger.addHandler(file_handler)

    # 同时输出到终端
    console_handler = logging.StreamHandler(sys.stdout)
    console_handler.setLevel(logging.INFO)
    console_handler.setFormatter(fmt)
    logger.addHandler(console_handler)

    return logger

# main.py 中使用
logger = setup_logger("blog-api")

@app.get("/api/posts")
def get_posts():
    logger.info("查询文章列表")
    # ...
    logger.info(f"返回 {len(result)} 篇文章")
    return result
```

#### 4.4 基础服务器监控

```bash

# 关注 Use% 接近 100% 的分区

# 按 q 退出
```

### 核心心法

> **不要等问题出现了才去查监控。** 每天花 1 分钟看一眼日志和服务器状态，能提前发现 80% 的问题。

## 第 5 节：持续部署入门（CI/CD）

### 详细讲解

#### 5.1 传统部署 vs 自动部署

**传统部署流程**：
```
1. 本地改代码
2. git add / commit / push
3. SSH 登录服务器
4. cd 到项目目录
5. git pull
6. source .venv/bin/activate
7. pip install -r requirements.txt（如果有新依赖）
8. sudo systemctl restart blog-api
```

每次改一行代码都要重复这 8 个步骤——麻烦且容易漏步骤。

**自动部署（CI/CD）流程**：
```
1. 本地改代码
2. git add / commit / push
3. 喝杯咖啡——GitHub Actions 自动完成 3-8 步
4. 刷新网站 → 已更新！
```

#### 5.2 GitHub Actions 入门

GitHub Actions 是 GitHub 内置的自动化工具。在你的仓库中创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to Server

on:
  push:
    branches: [main]
    # main 分支有 push → 自动触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    # 在 GitHub 提供的 Ubuntu 虚拟机上运行

    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        # 使用社区维护的 SSH Action
        with:
          host: ${{ secrets.SERVER_HOST }}
          # 从 GitHub Secrets 读取服务器 IP
          username: ${{ secrets.SERVER_USER }}
          # 从 GitHub Secrets 读取用户名
          key: ${{ secrets.SERVER_SSH_KEY }}
          # 从 GitHub Secrets 读取 SSH 私钥
          script: |
            cd /home/ubuntu/blog/backend
            git pull origin main
            source .venv/bin/activate
            pip install -r requirements.txt --quiet
            sudo systemctl restart blog-api
            echo "部署完成！"
```

#### 5.3 设置 GitHub Secrets

1. GitHub 仓库 → Settings → Secrets and variables → Actions
2. 添加以下 Secrets：

| Secret 名 | 值 |
|-----------|-----|
| `SERVER_HOST` | 你的服务器公网 IP |
| `SERVER_USER` | `ubuntu`（SSH 用户名） |
| `SERVER_SSH_KEY` | SSH 私钥的内容（`cat ~/.ssh/id_ed25519`） |

**注意**：服务器上需要把你的公钥添加到 `~/.ssh/authorized_keys`：
```bash
# 如果还没有 SSH 密钥对，先生成：
ssh-keygen -t ed25519 -C "github-actions-deploy"

# 添加公钥到 authorized_keys：
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
```

#### 5.4 出问题了怎么办——回滚

```bash
# 方案 1：Git revert
git revert HEAD     # 撤销最近一次提交
git push            # 触发自动部署

# 方案 2：服务器上手动 checkout 到之前版本
ssh ubuntu@服务器IP
cd /home/ubuntu/blog/backend
git log --oneline -5          # 看最近 5 个提交
git checkout abc1234          # 切换到之前的某个提交
sudo systemctl restart blog-api
```

### 核心心法

> **CI/CD 不是大公司的专利。** 就算是个人项目，`git push` 后自动部署也能省掉大量重复劳动。GitHub Actions 对公开仓库完全免费，每月 2000 分钟。

   - 在 FastAPI 中将 `print` 替换为 `logging`
   - 配置日志输出到文件（带轮转）
   - 在 Nginx 中找到 access.log，用 `tail -f` 查看实时访问日志

### 进阶题（选做）

5. **Nginx 反向代理**：
   - 配置 Nginx 反向代理：`api.yourdomain.com` → `localhost:8000`
   - 前端页面：`yourdomain.com` → `localhost:3000`

6. **自动部署**：
   - 创建 GitHub Actions workflow 文件
   - 配置 Secrets
   - 测试 `git push` → 自动部署

### 挑战题

7. **完整的运维体系**：
   - 所有服务都由 systemd/pm2 管理
   - systemd timer 设置日志定期清理
   - GitHub Actions 自动部署 + 部署失败自动通知（邮件/Webhook）
   - 编写一份给你的"运维手册"，记录：
     - 服务器 IP、域名
     - 各服务的启动/停止/重启命令
     - 日志位置
     - 常见问题和解决方案
