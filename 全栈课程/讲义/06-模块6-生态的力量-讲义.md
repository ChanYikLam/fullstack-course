## 第 1 节：pip 生态深度——找到需要的包

### 详细讲解

#### 1.1 PyPI 是什么？

PyPI（Python Package Index）是 Python 的官方包仓库。地址：https://pypi.org

你可以把它想象成手机的"应用商店"——只不过所有包都是免费的、开源的。

#### 1.2 如何评估一个包能不能用？

并不是 PyPI 上的每个包都值得用。评估一个包时问这 5 个问题：

| 评估维度 | 怎么看 | 好 | 差 |
|----------|--------|-----|-----|
| 下载量 | PyPI 页面 Statistics | 周下载 > 10 万 | 周下载 < 100 |
| 维护状态 | 最近 Release 时间 | 3 个月内更新过 | 2 年没更新 |
| 社区活跃度 | GitHub Issues / PR | 有人回复、PR 有 merge | Issue 没人理 |
| 文档质量 | 是否有 ReadTheDocs / 示例 | 有完整教程和 API 文档 | 只有一行 README |
| 许可证 | PyPI 页面 Meta → License | MIT / Apache / BSD | 没有许可证 = 不能合法使用 |

#### 1.3 版本号是什么意思？

```
requests == 2 . 31 . 0
            │    │    │
          主版本 次版本 修订版
          (不兼容 (新功能 (Bug
           改动)  但兼容) 修复)
```

- `2.31.0`：精确锁定这个版本
- `>=2.31.0`：至少 2.31.0，可以更高
- `~=2.31.0`：2.31.x 兼容版本（允许修订版升级）
- `^2.31.0`：2.x.x 兼容版本（允许次版本升级，Poetry 语法）

#### 1.4 常用工具包速查

| 包名 | 用途 | 一句话 |
|------|------|--------|
| `requests` | HTTP 客户端 | 发 HTTP 请求用这个 |
| `httpx` | 异步 HTTP 客户端 | requests 的异步版 |
| `python-dotenv` | 读取 `.env` 文件 | 密码和配置不放代码里 |
| `pydantic` | 数据校验 | FastAPI 内置，但也可以单独用 |
| `pytest` | 测试框架 | 写自动化测试 |
| `ruff` | 代码检查和格式化 | 一行命令搞定 lint + format |

## 第 2 节：数据库入门——SQLite 与 SQL 基础

### 详细讲解

#### 2.1 为什么文件不够用？

你可以把数据存成 JSON 文件：

```python
# 存
with open("users.json", "w") as f:
    json.dump(users, f)

# 查——噩梦开始
# "找出年龄 > 18 的用户" → 你得手动遍历
# "找出张三的所有订单" → 你得手动关联两个 JSON 文件
# "同时有 10 个人注册" → JSON 文件可能被写坏
```

数据库就是专门解决这些问题的软件。SQLite 是最轻量的——整个数据库就是一个文件。

#### 2.2 SQL 基础

SQL 是一门"描述你要什么"的语言，而不是"描述怎么做"的语言。

```sql
-- 不说"遍历所有行，如果 age > 18 就加到结果里"
-- 而是直接说"给我年龄大于 18 的用户"
SELECT * FROM users WHERE age > 18;
```

#### 2.3 表设计原则

| 原则 | 说明 | 例子 |
|------|------|------|
| 每列只存一个值 | 不要把多个值塞一列 | 错误：`"张三,李四"` 正确：分开两行 |
| 每行有唯一标识 | 主键 ID | `id INTEGER PRIMARY KEY` |
| 不存能算出来的东西 | 存生日，不存年龄 | 年龄 = 今天 - 生日 |
| 用外键关联 | 不要把所有数据放一张表 | `posts.user_id → users.id` |

### 课堂演示代码

```python
import sqlite3

# ===== 1. 连接数据库（不存在会自动创建） =====
conn = sqlite3.connect("demo.db")
cursor = conn.cursor()

# ===== 2. 创建表 =====
cursor.execute("""
    CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT NOT NULL,
        email TEXT UNIQUE NOT NULL,
        age INTEGER,
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP
    )
""")

# ===== 3. 插入数据 =====
cursor.execute(
    "INSERT INTO users (name, email, age) VALUES (?, ?, ?)",
    ("张三", "zhangsan@example.com", 25)
)
cursor.execute(
    "INSERT INTO users (name, email, age) VALUES (?, ?, ?)",
    ("李四", "lisi@example.com", 30)
)
# 注意：用 ? 占位符，不用字符串拼接——防止 SQL 注入！
conn.commit()  # 不要忘记提交！

# ===== 4. 查询 =====
cursor.execute("SELECT * FROM users")
rows = cursor.fetchall()
for row in rows:
    print(f"ID: {row[0]}, 姓名: {row[1]}, 邮箱: {row[2]}, 年龄: {row[3]}")

# 带条件查询
cursor.execute("SELECT name, age FROM users WHERE age > ?", (26,))
print("\n年龄大于 26 的用户：")
for row in cursor.fetchall():
    print(f"  {row[0]} - {row[1]}岁")

# 排序和限制
cursor.execute("SELECT * FROM users ORDER BY age DESC LIMIT 3")
print("\n年龄最大的 3 个用户：")
for row in cursor.fetchall():
    print(f"  {row[1]} - {row[3]}岁")

# ===== 5. 更新 =====
cursor.execute("UPDATE users SET age = ? WHERE name = ?", (26, "张三"))
conn.commit()

# ===== 6. 删除 =====
cursor.execute("DELETE FROM users WHERE name = ?", ("李四",))
conn.commit()

# ===== 7. 查看最终结果 =====
cursor.execute("SELECT * FROM users")
print("\n最终用户表：")
for row in cursor.fetchall():
    print(row)

conn.close()
```

### 核心心法

> **SQL 是声明式的**——你只需要说"我想要什么"，不需要说"怎么去拿"。数据库自己会找到最优的查询方式。这是 SQL 和普通编程语言最大的不同。

## 第 3 节：ORM——SQLAlchemy 入门

### 详细讲解

#### 3.1 为什么需要 ORM？

```python
# 不用 ORM——手动拼接 SQL（错误示范！）
name = input("请输入用户名：")  # 用户输入: '; DROP TABLE users; --
cursor.execute(f"SELECT * FROM users WHERE name = '{name}'")
# 实际执行的 SQL：
# SELECT * FROM users WHERE name = ''; DROP TABLE users; --'
#                                        ↑ 整张表被删了！

# 用 ORM——安全、清晰
user = session.query(User).filter(User.name == name).first()
# SQLAlchemy 自动处理转义——杜绝 SQL 注入
```

#### 3.2 SQLAlchemy 核心概念

```python
# 模型 = 表
class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True)
    name = Column(String(50))
    email = Column(String(100), unique=True)

# 操作 = Python 代码
new_user = User(name="张三", email="zhangsan@example.com")
session.add(new_user)       # INSERT
session.commit()

users = session.query(User).all()                        # SELECT *
user = session.query(User).filter(User.id == 1).first()  # SELECT WHERE
user.name = "新名字"                                      # UPDATE
session.delete(user)                                      # DELETE
session.commit()
```

### 课堂演示代码

```bash
# 安装 SQLAlchemy
pip install sqlalchemy
```

```python
from sqlalchemy import create_engine, Column, Integer, String, DateTime
from sqlalchemy.orm import DeclarativeBase, Session
from datetime import datetime

# ===== 1. 连接数据库 =====
# SQLite 最简单——数据库就是一个文件
engine = create_engine("sqlite:///orm_demo.db", echo=False)
# echo=True 可以看到每条生成的 SQL 语句

# ===== 2. 定义基类 =====
class Base(DeclarativeBase):
    pass

# ===== 3. 定义模型 =====
class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(50), nullable=False)
    email = Column(String(100), unique=True, nullable=False)
    age = Column(Integer)
    created_at = Column(DateTime, default=datetime.utcnow)

    def __repr__(self):
        return f"<User(id={self.id}, name='{self.name}', email='{self.email}')>"

# ===== 4. 创建表 =====
Base.metadata.create_all(engine)

# ===== 5. CRUD 操作 =====
with Session(engine) as session:
    # --- Create ---
    user1 = User(name="张三", email="zhangsan@example.com", age=25)
    user2 = User(name="李四", email="lisi@example.com", age=30)
    user3 = User(name="王五", email="wangwu@example.com", age=28)
    session.add_all([user1, user2, user3])
    session.commit()
    print("创建了 3 个用户")

    # --- Read ---
    # 查全部
    all_users = session.query(User).all()
    print(f"\n全部用户 ({len(all_users)} 人)：")
    for u in all_users:
        print(f"  {u}")

    # 条件查询
    adults = session.query(User).filter(User.age >= 18).all()
    print(f"\n成年人：")
    for u in adults:
        print(f"  {u.name} - {u.age}岁")

    # 查单个
    user = session.query(User).filter(User.email == "zhangsan@example.com").first()
    print(f"\n找到：{user}")

    # --- Update ---
    user.age = 26
    session.commit()
    print(f"更新后年龄：{user.age}")

    # --- Delete ---
    session.delete(user3)
    session.commit()
    print(f"删除王五后剩余 {session.query(User).count()} 人")

# 清理
import os
os.remove("orm_demo.db")
```

### 核心心法

> **ORM 让你用熟悉的 Python 对象操作数据库**，而不是写容易出错的 SQL 字符串。它就像一个翻译官——你说 Python，它说 SQL。SQL 注入的漏洞也在翻译的过程中被自动消除了。

## 第 4 节：前后端数据联通实战

### 详细讲解

#### 4.1 前端如何从后端获取数据？

在模块 3，前端数据是写死在 HTML/JS 里的。在模块 4，React 组件的 state 初始值是写死的。现在，数据应该来自后端 API：

```jsx
// 以前（数据写死在前端）
const [users, setUsers] = useState([
    { id: 1, name: "张三" },
    { id: 2, name: "李四" },
]);

// 现在（数据来自后端 API）
const [users, setUsers] = useState([]);

useEffect(() => {
    fetch("http://localhost:8000/api/users")
        .then(res => res.json())
        .then(data => setUsers(data))
        .catch(err => console.error("获取数据失败:", err));
}, []);
```

#### 4.2 CORS——为什么前端调后端会报错？

浏览器有一个安全机制叫**同源策略**——默认情况下，`localhost:5173`（Vite 前端）不能请求 `localhost:8000`（FastAPI 后端），因为端口不同，就算"不同源"。

解决方案：后端加 CORS 中间件（模块 5 已经配好了）：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 允许前端地址
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### 课堂演示代码

**后端 `main.py`**（FastAPI + SQLite）：

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import DeclarativeBase, Session

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],

class Base(DeclarativeBase):
    pass

class Todo(Base):
    __tablename__ = "todos"
    id = Column(Integer, primary_key=True, autoincrement=True)
    title = Column(String(200), nullable=False)
    completed = Column(Integer, default=0)

Base.metadata.create_all(engine)

# 添加测试数据
with Session(engine) as s:
    if s.query(Todo).count() == 0:
        s.add_all([
            Todo(title="学习 React 组件化"),
            Todo(title="理解数据驱动界面"),
            Todo(title="配置 FastAPI 后端"),
            Todo(title="实现前后端数据联通", completed=1),
        ])
        s.commit()

# API 接口
@app.get("/api/todos")
def get_todos():
    with Session(engine) as s:
        todos = s.query(Todo).all()
        return [
            {"id": t.id, "title": t.title, "completed": bool(t.completed)}
            for t in todos
        ]
```

**前端 `App.jsx`**（React + Vite）：
```jsx
import { useState, useEffect } from "react";

export default function App() {
    const [todos, setTodos] = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

            <h1>我的 Todo 列表</h1>

                {todos.map(todo => (

                        textDecoration: todo.completed ? "line-through" : "none",

                    }}>
                        {todo.title}
                        {todo.completed && " ✓"}
                    </li>
                ))}
            </ul>
        </div>
    );
}
```

## 第 5 节：用户认证基础——JWT

### 详细讲解

#### 5.1 为什么需要密码哈希？

```
不要存：                   要存（哈希后）：
┌──────────────────┐     ┌──────────────────────────┐
│ username: zhangsan│     │ username: zhangsan        │
│ password: 123456  │     │ password_hash: $2b$12$XyZ…│
└──────────────────┘     └──────────────────────────┘
     ↑                          ↑
  泄露 = 密码暴露            泄露 = 攻击者只知道哈希值
                                但无法反推原始密码
```

bcrypt 的特点：
- 同样的输入，每次哈希结果不同（因为每次用不同的"盐"）
- 验证密码时，能判断"这次输入的密码"是否和"之前哈希的那个密码"一致
- 单向函数——哈希 → 无法反推原始密码

#### 5.2 JWT 的完整工作流程

```
步骤 1: 用户注册
  POST /api/register  { username, password }
  → 密码 bcrypt 哈希 → 存入数据库 → 返回成功

步骤 2: 用户登录
  POST /api/login  { username, password }
  → 查数据库 → bcrypt 验证密码 → 签发 JWT → 返回 token

步骤 3: 用户访问受保护资源
  GET /api/profile  (Header: Authorization: Bearer <token>)
  → 后端验证 token 签名 → 解析出用户 ID → 查询数据 → 返回

步骤 4: Token 过期
  → 用户需要重新登录获取新 token
```

### 课堂演示代码


**auth_demo.py**：
```python
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from fastapi.middleware.cors import CORSMiddleware
from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import DeclarativeBase, Session
from pydantic import BaseModel
from passlib.context import CryptContext
from jose import JWTError, jwt
from datetime import datetime, timedelta
import os

# ===== 配置 =====
SECRET_KEY = os.getenv("SECRET_KEY", "dev-secret-key-change-in-production")
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

app = FastAPI()
security = HTTPBearer()
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["*"], allow_headers=["*"])

# ===== 数据库 =====
engine = create_engine("sqlite:///auth_demo.db")

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, autoincrement=True)
    username = Column(String(50), unique=True, nullable=False)
    password_hash = Column(String(200), nullable=False)

Base.metadata.create_all(engine)

# ===== Pydantic 模型 =====
class RegisterRequest(BaseModel):
    username: str
    password: str

class LoginRequest(BaseModel):
    username: str
    password: str

# ===== 工具函数 =====
def create_token(user_id: int) -> str:
    expire = datetime.utcnow() + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    payload = {"sub": str(user_id), "exp": expire}
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

def get_current_user(credentials: HTTPAuthorizationCredentials = Depends(security)):
    try:
        payload = jwt.decode(credentials.credentials, SECRET_KEY, algorithms=[ALGORITHM])
        user_id = int(payload.get("sub"))
    except JWTError:
        raise HTTPException(status_code=401, detail="无效的 Token")

    with Session(engine) as s:
        user = s.query(User).filter(User.id == user_id).first()
        if not user:
            raise HTTPException(status_code=401, detail="用户不存在")
        return user

# ===== 接口 =====
@app.post("/api/register")
def register(req: RegisterRequest):
    with Session(engine) as s:
        if s.query(User).filter(User.username == req.username).first():
            raise HTTPException(status_code=400, detail="用户名已存在")

        user = User(
            username=req.username,
            password_hash=pwd_context.hash(req.password)  # bcrypt 哈希
        )
        s.add(user)
        s.commit()
        return {"message": "注册成功"}

@app.post("/api/login")
def login(req: LoginRequest):
    with Session(engine) as s:
        user = s.query(User).filter(User.username == req.username).first()
        if not user or not pwd_context.verify(req.password, user.password_hash):
            raise HTTPException(status_code=401, detail="用户名或密码错误")

        token = create_token(user.id)
        return {"access_token": token, "token_type": "bearer"}

@app.get("/api/me")
def get_me(user: User = Depends(get_current_user)):
    return {"id": user.id, "username": user.username}
```

```bash
# 运行
uvicorn auth_demo:app --reload

# 测试
# 1. 注册
curl -X POST http://localhost:8000/api/register \
  -H "Content-Type: application/json" \
  -d '{"username": "test", "password": "123456"}'

# 2. 登录
curl -X POST http://localhost:8000/api/login \
  -H "Content-Type: application/json" \
  -d '{"username": "test", "password": "123456"}'
# 返回: {"access_token": "eyJ...", "token_type": "bearer"}

# 3. 使用 token 访问受保护接口
curl http://localhost:8000/api/me \
  -H "Authorization: Bearer 刚才拿到的token"
# 返回: {"id": 1, "username": "test"}

# 4. 不带 token 访问 → 401
curl http://localhost:8000/api/me
# 返回: {"detail": "Not authenticated"}
```

   - 记录它们的：最新版本、最近更新时间、GitHub Star 数、许可证类型

2. **SQLite 练习**：
   - 用 Python 的 `sqlite3` 模块创建一个"图书管理"数据库
   - 包含表 `books`：id、title、author、year、rating
   - 插入至少 5 本书的数据
   - 实现：查询所有书、按年份排序、查询评分 > 8.0 的书

3. **SQLAlchemy 迁移**：
   - 用 SQLAlchemy 重写上面的图书管理功能
   - 对比两种方式的代码量和安全性

4. **前后端联通**：
   - 创建 FastAPI 后端（提供 `/api/books` 接口）
   - 创建 React 前端（展示图书列表）
   - 前端从后端获取数据并展示

### 进阶题（选做）

5. **JWT 实现完整的用户系统**：
   - 实现注册、登录、查看个人信息、修改密码
   - 前端实现登录表单和 token 管理

6. **分页实现**：
   - 给 `/api/books` 接口添加分页参数 `?page=1&size=10`
   - 返回 `{"items": [...], "total": 100, "page": 1, "size": 10}`

### 挑战题

7. **设计并实现一个小型应用的后端**：
   - 至少 2 张表（有外键关联）
   - 完整的 CRUD + 用户认证
   - 前端调用后端展示数据
