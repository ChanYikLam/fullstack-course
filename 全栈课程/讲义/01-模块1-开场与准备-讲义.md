## 课前阅读（10 分钟）

### 这门课为什么叫"零到全栈"？

"零"有两层意思：
1. **零基础**——不需要任何编程背景，会开机、会打字就能学
2. **零到一**——从什么都没有开始，最终做出一款真正可用的产品

"全栈"不是说你什么都精通。它说的是：**你能从前端页面、到后端逻辑、到服务器部署，把整条链路跑通**。你不是只会其中一小段的"螺丝钉"，而是能理解全局、对结果负责的"建筑师"。

### AI 时代的学习逻辑变了

过去学编程，你要：
- 花几周学语法 → 花几周学框架 → 花几周学工具链 → 花几周做项目

这个过程动辄半年起步。

现在 AI 可以写代码了，但 AI 不会替你做决策、不会替你理解产品逻辑、不会替你把代码部署到服务器。所以现在学习的重心从"怎么写代码"变成了"怎么管理和组织代码"。

**所以这门课的学习逻辑是**：
1. 看视频 → 理解"是什么"和"为什么"
2. 跟着实操 → 亲手跑通每一步
3. 做作业 → 验证自己真的理解了
4. 用 AI 辅助 → 但永远是你做决策、AI 做执行

## 第 1 节：为什么在 AI 时代还要学全栈开发

**视频**: [B 站链接](https://www.bilibili.com/video/BV16jREBdEX5) | **时长**: ~7 分钟

### 详细讲解

#### 1.1 一个网站到底由几部分组成？

想象你要做一个"个人博客"网站。当你打开浏览器输入网址，看到的那个页面，背后其实有三层东西在协同工作：

```
┌──────────────────────────────────────┐
│  你在浏览器看到的页面（前端）          │
│  - 文字、图片、按钮、动画              │
├──────────────────────────────────────┤
│  页面背后处理数据的部分（后端）         │
│  - 登录验证、数据存储、搜索           │
├──────────────────────────────────────┤
│  让这一切跑起来的环境（运维/部署）      │
│  - 服务器、域名、HTTPS、数据库        │
└──────────────────────────────────────┘
```

**全栈开发**就是：你能把这三层都搞定。

#### 1.2 "代码管理"vs"写代码"——这门课的核心差异

```
传统编程课教你的：          这门课教你的：
┌─────────────────┐      ┌─────────────────┐
│ for(i=0;i<n;i++)│      │ 这个功能该用      │
│ {               │      │ GET还是POST?      │
│   sum += arr[i] │      │                 │
│ }               │      │ AI写的代码该      │
│                 │      │ 放在哪个文件夹？   │
│ 记语法、背API    │      │                 │
│                 │      │ 怎么让代码        │
│                 │      │ 在服务器上跑起来？ │
└─────────────────┘      └─────────────────┘
```

**为什么这个区分很重要？**

因为 AI 已经能写出 80 分的代码，但它不知道：
- 代码应该放在项目的哪个位置
- 这段代码应该怎么跟其他部分连接
- 代码出错了应该查哪一层
- 怎样把代码变成一个别人能访问的产品

这就好比：AI 是熟练的建筑工人（能很快砌墙），但你是建筑师（决定房子怎么设计、各个房间怎么连接、水电怎么走）。

#### 1.3 程序员 vs 工程师

| | 程序员 | 工程师 |
|------|------|------|
| 核心技能 | 写代码 | 做系统 |
| 关注点 | 这段代码怎么写 | 这个系统怎么工作 |
| 对 AI 的态度 | "AI 会不会取代我？" | "AI 能帮我省多少时间？" |
| 负责范围 | 一个函数、一个组件 | 从需求到上线的完整链路 |

**这门课培养的是工程师思维。**

## 第 3 节：课前准备

**视频**: [B 站链接](https://www.bilibili.com/video/BV1BhReBaEJw) | **时长**: ~4 分钟

### 详细讲解

#### 3.1 需要准备的软件

##### VS Code 安装

VS Code 是目前最流行的代码编辑器，免费且跨平台。

**macOS**：
1. 访问 https://code.visualstudio.com/ 下载 Mac 版本
2. 把下载的 `.zip` 解压，把 `Visual Studio Code.app` 拖到 `应用程序` 文件夹
3. 打开 VS Code，按 `Cmd+Shift+P`，输入 `shell command`，选择 "Install 'code' command in PATH"
   - 这样以后在终端里输入 `code .` 就能用 VS Code 打开当前文件夹

**Windows**：
1. 访问 https://code.visualstudio.com/ 下载 Windows 版本
2. 运行安装程序，一路默认即可
3. 安装时勾选 "Add to PATH" 选项

##### Chrome 浏览器

Chrome 自带的开发者工具（F12）是前端开发必备的调试利器。整个课程会频繁用到。

##### 终端（Terminal）

- **macOS**：打开 `启动台` → `其他` → `终端`（或按 `Cmd+空格` 搜索 "Terminal"）
- **Windows**：建议安装 Windows Terminal（从 Microsoft Store 免费下载），或使用 PowerShell

#### 3.2 需要注册的账号

| 平台 | 用途 | 注册地址 |
|------|------|----------|
| GitHub | 代码托管、版本管理 | https://github.com |
| 任意云厂商 | 租云服务器（模块 2.4） | 腾讯云/阿里云/华为云等 |

> **GitHub 账号现在就注册好。** 这是整个课程的"基础设施"——你会把代码存在 GitHub 上，你的服务器也会从 GitHub 拉取代码。

#### 3.3 学习建议

1. **不要跳课** — 每个模块的前后依赖关系很强，跳一节可能后面全跟不上
2. **动手 > 听懂** — 看视频是 20%，动手实操是 80%
3. **允许卡住** — 卡住是学习的一部分，不是失败
4. **善用 AI** — 遇到看不懂的代码，可以让 AI 给你解释
5. **先理解再记忆** — 不要死记硬背命令，理解这些命令在做什么更重要

#### 3.4 学习节奏建议

| 节奏 | 每周投入 | 适合人群 |
|------|----------|----------|
| 快速 | 10-15 小时 | 有充裕时间、想尽快学完 |
| 正常 | 5-8 小时 | 在职/在校，业余时间学习 |
| 细品 | 2-3 小时 | 不赶时间，想深入理解每个概念 |

## 课后作业

### 基础题（必做）

1. **用自己的话解释**（写一段文字，不少于 200 字）：
   - 什么是"全栈开发"？
   - 为什么在 AI 时代学习全栈开发反而更有意义？
   - "管理代码"和"写代码"有什么区别？

2. **环境准备**（截图验证）：
   - [ ] 安装 VS Code，打开后截图
   - [ ] 打开终端（Mac：Terminal / Win：PowerShell），输入 `whoami` 截图
   - [ ] 注册 GitHub 账号，截图个人主页

3. **课程预期**：
   - 学完这门课之后，你最想做出一个什么样的产品？写一段产品构想（不限字数）。

### 进阶题（选做）

4. **探索 VS Code**：
   - 安装 VS Code 后，尝试安装一个插件（比如 "Chinese (Simplified) Language Pack" 中文语言包）
   - 在 VS Code 里新建一个文件，随意写点内容，保存为 `.md` 文件（Markdown 格式）
   - 按 `Ctrl+Shift+V`（Mac: `Cmd+Shift+V`）预览 Markdown 效果

5. **了解 Markdown 语法**：
   - 在网上搜索 "Markdown 语法"，学习以下几个基本语法：
     - 标题（`# ## ###`）
     - 加粗（`**文字**`）
     - 列表（`- 项目`）
     - 链接（`[文字](网址)`）
     - 代码块（` ``` 代码 ``` `）
   - 用 Markdown 写一篇短文介绍自己，保存为 `自我介绍.md`

6. **思考题**：
   - 你在生活中使用过哪些"前端"产品？（网站、App 等）
   - 你觉得这些产品背后有没有"后端"？试着猜一猜后端在做什么。
   - 找一个你喜欢的网站，按下 F12（或右键 → 检查），随意看看里面有什么。你看到了什么有趣的东西？
