## 课前阅读（20 分钟）

### 写代码之前最重要的一步

很多人学完基础之后，打开编辑器就想写代码。结果写了 200 行就卡住了——不知道接下来该写什么。

这不是技术问题，是**规划问题**。

盖房子不打图纸就砌墙，砌到一半必然塌。做软件也是一样。这个模块要教你的，就是在写第一行代码之前，先花 30 分钟把"图纸"画好。

## 第 1 节：项目规划与架构设计

### 详细讲解

#### 1.1 从想法到图纸的四步法

**第一步：功能列表**——"这个系统要能做什么？"

```
个人博客功能列表：
□ 用户注册
□ 用户登录/登出
□ 写文章（标题、内容、封面图）
□ 编辑文章
□ 删除文章
□ 文章列表（首页，分页显示）
□ 文章详情页
□ 发表评论
□ 评论列表
□ 管理员删除评论
```

**第二步：页面树**——"有哪些页面？"

```
/                    → 首页（文章列表）
/login               → 登录页
/register            → 注册页
/posts/new           → 写文章
/posts/[id]          → 文章详情
/posts/[id]/edit     → 编辑文章
/admin               → 管理后台（我的文章列表）
```

**第三步：数据模型**——"数据库里要存什么？"

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│    users     │     │    posts     │     │   comments   │
├─────────────┤     ├─────────────┤     ├─────────────┤
│ id (PK)     │←────│ user_id (FK)│←────│ post_id (FK)│
│ username    │     │ id (PK)     │     │ id (PK)     │
│ password    │     │ title       │     │ author_name │
│ created_at  │     │ content     │     │ content     │
└─────────────┘     │ cover_url   │     │ created_at  │
                    │ created_at  │     └─────────────┘
                    │ updated_at  │
                    └─────────────┘

PK = 主键 (Primary Key)
FK = 外键 (Foreign Key)——关联另一张表
```

**第四步：API 设计**——"前后端怎么通信？"

```
认证相关：
POST   /api/auth/register     注册
POST   /api/auth/login        登录
GET    /api/auth/me            获取当前用户信息

文章相关（公开）：
GET    /api/posts              获取文章列表 ?page=1&size=10
GET    /api/posts/:id          获取文章详情

文章相关（需登录）：
POST   /api/posts              创建文章
PUT    /api/posts/:id          编辑文章
DELETE /api/posts/:id          删除文章

评论相关：
GET    /api/posts/:id/comments       获取文章评论
POST   /api/posts/:id/comments       发表评论
DELETE /api/comments/:id             删除评论（需登录）

文件上传：
POST   /api/upload             上传文件（封面图）
```

### 核心心法

> **图纸画好了，编码就是"按图施工"。** 如果施工时发现图纸有问题——那是好事，改图纸比改代码快多了。

## 第 2 节：用户系统完整实现

### 详细讲解

#### 2.1 密码应该怎么存？

```
错误做法：                        正确做法：
password = "123456"              password_hash = bcrypt.hash("123456")
存入数据库                       存入数据库

数据库泄露 → 密码全暴露           数据库泄露 → 攻击者只有哈希值，无法还原
```

bcrypt 的几个特性：
- **加盐**：同样的密码，两次哈希结果不同（因为随机盐不同）
- **慢**：故意设计成计算慢（0.3 秒左右），防止暴力破解
- **不可逆**：哈希 → 无法反推原始密码

#### 2.2 注册和登录的前后端交互

```
注册流程：
前端表单（用户名+密码）→ POST /api/register → 
后端检查用户名是否已存在 → 不存在 → bcrypt 哈希密码 → 存入数据库 → 
返回 {"message": "注册成功"}

登录流程：
前端表单（用户名+密码）→ POST /api/login → 
后端查数据库 → bcrypt 验证密码 → 密码正确 → 签发 JWT → 
返回 {"access_token": "eyJ..."} →
前端把 token 存到 localStorage

后续请求：
前端请求 → Header: Authorization: Bearer <token> → 
后端验证 token → 解析出用户身份 → 处理请求
```

### 课堂演示代码

#### 注册页面（React）

```jsx
import { useState } from "react";

export default function RegisterPage() {
    const [username, setUsername] = useState("");
    const [password, setPassword] = useState("");
    const [message, setMessage] = useState("");
    const [isError, setIsError] = useState(false);

    async function handleSubmit(e) {
        e.preventDefault();
        setMessage("");

        try {
            const res = await fetch("http://localhost:8000/api/auth/register", {
                method: "POST",
                headers: { "Content-Type": "application/json" },
                body: JSON.stringify({ username, password }),
            });
            const data = await res.json();

            if (res.ok) {
                setMessage("注册成功！即将跳转到登录页...");
                setIsError(false);
                setTimeout(() => {
                    window.location.href = "/login";
                }, 1500);
            } else {
                setMessage(data.detail || "注册失败");
                setIsError(true);
            }
        } catch (err) {
            setMessage("网络错误，请稍后重试");
            setIsError(true);
        }
    }

    return (
        <div>
            <h1>注册</h1>
            <form onSubmit={handleSubmit}>
                <input
                    type="text"
                    placeholder="用户名"
                    value={username}
                    onChange={e => setUsername(e.target.value)}
                    required
                />
                <input
                    type="password"
                    placeholder="密码"
                    value={password}
                    onChange={e => setPassword(e.target.value)}
                    required
                    minLength={6}
                />
                <button type="submit">注册</button>
            </form>
            {message && (
                <p style={{ color: isError ? "red" : "green" }}>{message}</p>
            )}
        </div>
    );
}
```

#### Token 管理工具

```js
// utils/auth.js

const TOKEN_KEY = "blog_access_token";

export function saveToken(token) {
    localStorage.setItem(TOKEN_KEY, token);
}

export function getToken() {
    return localStorage.getItem(TOKEN_KEY);
}

export function removeToken() {
    localStorage.removeItem(TOKEN_KEY);
}

export function isLoggedIn() {
    return !!getToken();
}

export function getAuthHeaders() {
    const token = getToken();
    return token
        ? { Authorization: `Bearer ${token}` }
        : {};
}

// 使用示例：
// fetch("/api/posts", { headers: getAuthHeaders() })
```

## 第 3 节：CRUD 完整实现

### 详细讲解

#### 3.1 CRUD 的完整生命周期

以"文章"为例，下面是完整的 CRUD 流程：

**Create（创建）**：
```
前端写文章表单 → 点"发布" → POST /api/posts（带 token）→
后端验证身份 → 校验数据 → 写入数据库 → 返回新文章 → 前端跳转到文章详情
```

**Read（读取列表）**：
```
前端首页 → useEffect → GET /api/posts?page=1&size=10 →
后端查询数据库 → 分页 → 返回列表 → 前端渲染文章卡片
```

**Update（更新）**：
```
前端编辑表单 → 点"保存" → PUT /api/posts/:id（带 token）→
后端验证身份 → 验证"你是这篇文章的作者吗" → 更新数据库 → 返回更新后的文章
```

**Delete（删除）**：
```
前端点"删除" → 弹窗确认 → DELETE /api/posts/:id（带 token）→
后端验证身份 → 验证"你是这篇文章的作者吗" → 删除数据库记录 → 返回 204
```

#### 3.2 分页实现

```python
# FastAPI 分页参数
from fastapi import Query

@app.get("/api/posts")
def get_posts(
    page: int = Query(1, ge=1),
    size: int = Query(10, ge=1, le=100)
):
    offset = (page - 1) * size
    with Session(engine) as s:
        total = s.query(Post).count()
        posts = s.query(Post).order_by(Post.created_at.desc())\
                 .offset(offset).limit(size).all()
        return {
            "items": [format_post(p) for p in posts],
            "total": total,
            "page": page,
            "size": size,
            "pages": (total + size - 1) // size
        }
```

#### 3.3 权限验证——"这是你的文章吗？"

```python
def verify_post_owner(post_id: int, user: User = Depends(get_current_user)):
    with Session(engine) as s:
        post = s.query(Post).filter(Post.id == post_id).first()
        if not post:
            raise HTTPException(status_code=404, detail="文章不存在")
        if post.user_id != user.id:
            raise HTTPException(status_code=403, detail="你没有权限操作这篇文章")
        return post

@app.put("/api/posts/{post_id}")
def update_post(post_id: int, req: UpdatePostRequest,
                post: Post = Depends(verify_post_owner)):
    # post 已经验证了身份和所有权——直接更新即可
    with Session(engine) as s:
        post.title = req.title
        post.content = req.content
        s.commit()
        return format_post(post)
```

### 核心心法

> **CRUD 加上认证 = 90% 的应用后端。** 你会发现无论是博客、电商、社交、论坛——后端本质上都是同样的模式：认证 + CRUD + 权限检查。

## 第 4 节：文件上传与静态资源管理

### 详细讲解

#### 4.1 文件上传的完整流程

```
前端：
1. 用户选择文件（<input type="file">）
2. 创建 FormData，append 文件
3. POST /api/upload（multipart/form-data）

后端：
1. 接收 UploadFile 对象
2. 校验文件类型（不是扩展名，是真实 MIME 类型）
3. 校验文件大小（限制上限）
4. 生成唯一文件名（防止覆盖和路径穿越）
5. 保存到 uploads/ 目录（或云对象存储）
6. 返回可访问的 URL
```

#### 4.2 安全要求

```python
import os, uuid
from fastapi import UploadFile, HTTPException

ALLOWED_TYPES = ["image/jpeg", "image/png", "image/gif", "image/webp"]
MAX_SIZE = 5 * 1024 * 1024  # 5MB

async def save_upload_file(file: UploadFile) -> str:
    # 1. 检查文件大小
    contents = await file.read()
    if len(contents) > MAX_SIZE:
        raise HTTPException(400, f"文件过大，最大 {MAX_SIZE // 1024 // 1024}MB")

    # 2. 检查文件类型（检查真实 MIME，不是扩展名）
    import magic  # pip install python-magic
    mime = magic.from_buffer(contents[:1024], mime=True)
    if mime not in ALLOWED_TYPES:
        raise HTTPException(400, f"不支持的文件类型：{mime}")

    # 3. 生成唯一文件名
    ext = os.path.splitext(file.filename)[1] if file.filename else ".jpg"
    filename = f"{uuid.uuid4()}{ext}"

    # 4. 保存
    filepath = os.path.join("uploads", filename)
    with open(filepath, "wb") as f:
        f.write(contents)

    return f"/static/{filename}"
```

## 第 5 节：项目优化与重构

### 详细讲解

#### 5.1 代码坏味道——什么时候该重构？

| 坏味道 | 表现 | 怎么办 |
|--------|------|--------|
| 重复代码 | 同样的逻辑出现在 3 个接口里 | 抽成工具函数 |
| 长函数 | 一个函数超过 50 行 | 拆成多个小函数 |
| 魔法数字 | 代码里到处都是 `5`、`10`、`"secret"` | 定义常量 |
| 硬编码配置 | 数据库地址写死在代码里 | 用环境变量 `.env` |

#### 5.2 重构前 vs 重构后

**重构前（所有逻辑堆在一起）**：
```python
@app.get("/api/posts")
def get_posts():
    # ❌ 密码写死在代码里
    engine = create_engine("sqlite:///blog.db")
    s = Session(engine)
    # ❌ 重复的分页逻辑
    page = 1
    size = 10
    offset = (page - 1) * size
    posts = s.query(Post).offset(offset).limit(size).all()
    # ❌ print 调试
    print(f"查询到 {len(posts)} 篇文章")
    return [{"id": p.id, "title": p.title} for p in posts]
```

**重构后（关注点分离）**：
```python
# database.py —— 数据库连接
from sqlalchemy import create_engine
from sqlalchemy.orm import Session
import os

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///blog.db")
engine = create_engine(DATABASE_URL)

def get_db():
    with Session(engine) as s:
        yield s

# schemas.py —— 数据模型
from pydantic import BaseModel

class PostOut(BaseModel):
    id: int
    title: str
    content: str
    created_at: str

class PaginatedResponse(BaseModel):
    items: list
    total: int
    page: int
    size: int
    pages: int

# services.py —— 业务逻辑
def get_posts_page(db, page=1, size=10):
    total = db.query(Post).count()
    posts = db.query(Post).order_by(Post.created_at.desc())\
               .offset((page - 1) * size).limit(size).all()
    return {
        "items": posts,
        "total": total,
        "page": page,
        "size": size,
        "pages": (total + size - 1) // size
    }

# main.py —— API 路由（简洁！）
import os
from dotenv import load_dotenv
load_dotenv()

@app.get("/api/posts", response_model=PaginatedResponse)
def get_posts(page: int = 1, db: Session = Depends(get_db)):
    logger.info(f"查询文章列表：page={page}")
    return get_posts_page(db, page)
```

### 核心心法

> **重构不是重写。** 重构是在不改变外部行为的前提下，改善代码的内部结构。用户感受不到任何变化，但开发者感受到的代码质量是天壤之别。
