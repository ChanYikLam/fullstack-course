## 第 1 节：域名注册与 DNS 配置

### 知识点

| 知识点 | 说明 |
|--------|------|
| 域名注册 | 在域名注册商（阿里云、腾讯云、Namecheap 等）购买域名 |
| 域名后缀 | `.com`、`.cn`、`.xyz` 等——价格不同，功能一样 |
| DNS 解析记录 | A 记录（域名 → IP）、CNAME 记录（域名 → 另一个域名）、AAAA 记录（IPv6） |
| A 记录设置 | 主机记录 `@`（根域名）+ 记录值（服务器公网 IP） |
| WWW 解析 | 主机记录 `www` + 记录值（服务器公网 IP），或 CNAME 到根域名 |
| DNS 生效时间 | 修改后可能需要几分钟到几小时全球生效 |
| Nginx `server_name` | 告诉 Nginx"哪些域名的请求归我管" |

### 实操步骤

```bash
# 1. 购买域名（浏览器操作）
# 2. 在 DNS 管理中添加 A 记录：
#    主机记录: @  → 记录值: 你的服务器公网 IP
#    主机记录: www → 记录值: 你的服务器公网 IP

# 3. 修改 Nginx 配置
sudo vim /etc/nginx/sites-available/default

# 添加 server_name
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    root /var/www/your-project;
    index index.html;
}

# 4. 检查配置并重启
sudo nginx -t
sudo systemctl restart nginx

# 5. 浏览器访问你的域名——应该看到你的网站！
```

### 核心理解

> **域名就是 IP 的文字别名。** A 记录 = "yourdomain.com 的 IP 是 123.45.67.89"。你只改这一行，全世界的人就能用域名访问你的服务器。

## 第 2 节：HTTPS——Let's Encrypt 免费证书

### 知识点

| 知识点 | 说明 |
|--------|------|
| 为什么需要 HTTPS | HTTP 是明文传输——中间任何人都能看到（密码、银行卡号等）；HTTPS 加密 |
| SSL/TLS 证书 | 证明"你就是 youdomain.com"的数字证书 |
| Let's Encrypt | 免费、自动化、开放的证书颁发机构 |
| Certbot | Let's Encrypt 官方客户端，自动申请和配置证书 |
| 证书有效期 | 90 天——Certbot 可以设置自动续期 |
| HTTP → HTTPS 重定向 | 强制用户走加密连接（301 重定向） |
| 443 端口 | HTTPS 的默认端口——确保在安全组中放行 |

### 实操步骤

```bash
# 在服务器上

# 1. 安装 Certbot（Ubuntu）
sudo apt install certbot python3-certbot-nginx -y

# 2. 申请证书
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
# 按提示输入邮箱（用于证书到期通知）
# 同意服务条款
# 选择是否重定向 HTTP 到 HTTPS（选 2——重定向）

# 3. Certbot 会自动修改 Nginx 配置
# 查看修改后的配置：
sudo cat /etc/nginx/sites-available/default
# 你会发现多了 443 端口的 server 块，以及 SSL 证书路径

# 4. 测试自动续期
sudo certbot renew --dry-run
# 如果成功，说明自动续期配置正确

# 5. 浏览器访问 https://yourdomain.com
# 看到锁图标！说明 HTTPS 已启用
```

### 安全组提醒

确保云平台安全组放行了 **443 端口**（TCP 入站），否则 HTTPS 请求到不了服务器。

### 核心理解

> **HTTPS 不是高级功能，是现代网站的标配。** 有了 Let's Encrypt，配置 HTTPS 只需要一条命令。没有理由不用 HTTPS。

## 第 3 节：进程守护——服务不能挂

### 知识点

| 知识点 | 说明 |
|--------|------|
| 为什么需要进程守护 | `python3 main.py` 是一次性的——终端关了、服务器重启了，服务就停了 |
| 进程管理器 | 负责启动服务、监控运行状态、挂了自动重启、开机自启 |
| systemd | Linux 系统自带的进程管理器（推荐） |
| pm2 | Node.js 生态的进程管理器（前端项目常用） |
| Supervisor | Python 社区传统的进程管理器 |

### systemd 配置 FastAPI 服务

```bash
# 1. 创建服务配置文件
sudo vim /etc/systemd/system/myapp.service
```

```ini
[Unit]
Description=My FastAPI Application
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/myapp
Environment="PATH=/home/ubuntu/myapp/.venv/bin"
ExecStart=/home/ubuntu/myapp/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
# 2. 启动服务
sudo systemctl daemon-reload   # 重新加载配置
sudo systemctl start myapp     # 启动
sudo systemctl enable myapp    # 设置开机自启

# 3. 日常管理
sudo systemctl status myapp    # 查看状态
sudo systemctl restart myapp   # 重启
sudo systemctl stop myapp      # 停止
sudo journalctl -u myapp -f    # 实时查看日志
```

### pm2 管理 Next.js 前端

```bash
# 安装 pm2
npm install -g pm2

# 启动 Next.js 应用
pm2 start npm --name "frontend" -- start

# 设置开机自启
pm2 startup
pm2 save

# 日常管理
pm2 status          # 查看所有进程状态
pm2 logs frontend   # 查看日志
pm2 restart frontend
pm2 stop frontend
```

### 核心理解

> **进程守护 = 给服务买保险。** 出错了自动重启，服务器重启自动恢复，你晚上可以安心睡觉。`systemd`（Python 后端）和 `pm2`（Node 前端）是最常用的组合。

## 第 4 节：日志与监控

### 知识点

| 知识点 | 说明 |
|--------|------|
| 日志的作用 | 出问题时，日志是你唯一的线索——没有日志，就是"蒙着眼睛修 bug" |
| 日志级别 | DEBUG（调试）< INFO（信息）< WARNING（警告）< ERROR（错误）< CRITICAL（严重） |
| Python logging | 标准库，替代 `print`——可控制输出位置、格式、级别 |
| Nginx 日志 | `access.log`（每次请求记录）、`error.log`（出错记录） |
| 日志轮转 | 日志文件会越来越大，需要定期切割和清理（`logrotate`） |
| 基础监控 | `htop`（CPU/内存）、`df -h`（磁盘空间）、`systemctl status`（服务状态） |
| 告警 | 服务挂了怎么办？——Uptime Kuma（自托管监控 + 通知） |

### 日志配置示例

```python
# Python logging 基本配置
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.FileHandler("app.log"),      # 输出到文件
        logging.StreamHandler(),             # 同时输出到终端
    ]
)

logger = logging.getLogger(__name__)
logger.info("应用启动")
logger.warning("这是一条警告")
logger.error("发生错误", exc_info=True)       # 附带异常堆栈
```

### 核心理解

> **日志和监控是上线的底线。** 没日志 = 出问题只能猜。有日志 = 出问题能查。有监控 = 出问题能第一时间知道。

## 第 5 节：持续部署入门（CI/CD）

### 知识点

| 知识点 | 说明 |
|--------|------|
| CI/CD 是什么 | Continuous Integration / Continuous Deployment——自动化构建 + 自动化部署 |
| 传统部署流程 | 本地改代码 → 手动上传服务器 → 手动重启服务（慢、易出错） |
| CI/CD 部署流程 | 本地 `git push` → GitHub Actions 自动构建 → 自动部署到服务器 → 自动重启 |
| GitHub Actions | GitHub 内置的 CI/CD 工具——免费额度够个人项目用 |
| 部署脚本 | SSH 登录服务器 → `git pull` → `systemctl restart` |
| 回滚 | 出问题了怎么办——重新部署上一个版本或 `git revert` |

### GitHub Actions 部署示例

```yaml
# .github/workflows/deploy.yml
name: Deploy to Server

on:
  push:
    branches: [main]      # main 分支有推送就触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /var/www/my-project
            git pull origin main
            source .venv/bin/activate
            pip install -r requirements.txt
            sudo systemctl restart myapp
```

### 核心理解

> **CI/CD 不是大公司的专利。** 个人项目同样受益——`git push` 之后自动部署，省掉每次手动 SSH + pull + restart 的重复劳动。GitHub Actions 对公开仓库完全免费。
